# Product Direction

## 定位

> 一个可靠、隐私优先、以本地音乐完成晨间唤醒的 macOS 音乐闹钟。

## 对齐的产品范式

| 产品范式 | 值得对齐的能力 | Music Alarm 的取舍 |
|---|---|---|
| 系统时钟类闹钟 | 重复规则、多闹钟、后台可靠触发 | 优先修复调度和睡眠恢复，减少“刚好每分钟检查一次”的脆弱性 |
| 任务型起床闹钟 | 起床确认、完成状态、可选挑战 | 加入可选“我已经真正起床”，让用户决定是否启用，不强迫所有人做任务 |
| 渐进式唤醒产品 | 渐入、唤醒窗口、逐步提高声音 | 保留本地音频渐入，后续评估唤醒窗口，避免一次加入过多复杂状态 |
| 桌面常驻工具 | 登录启动、窗口关闭后继续运行、系统通知 | 先保证后台运行和弹窗可操作，再补充登录启动和通知集成 |

## 差异化强项

1. **隐私优先**：本地音频和闹钟数据留在用户 Mac 上，不依赖云端账号和第三方音乐服务。
2. **可迁移**：用户可以把应用放在不同目录，跨开发版本继续使用同一份闹钟列表和音乐库。
3. **可解释的可靠性**：错过闹钟、音频失效、数据损坏和播放 fallback 都有明确状态，不用“看起来保存成功”掩盖失败。
4. **晨间状态确认可选**：普通用户可以一键停止；需要确认的人再打开“我已经真正起床”。
5. **本地音乐可控**：用户拥有对音频文件的控制，不受外部播放器登录、网络状态或播放策略变化影响。
6. **确认强度可调**：普通闹钟保持一键停止；需要真正起床的人可以打开确认状态，并在主列表继续完成确认。

## 不做的方向

- 不把第三方流媒体自动播放作为核心闹钟能力。
- 不在本地文档中保存账号密码、Cookie、Token 或外部服务密钥。
- 不用复杂的强制任务阻挡所有用户关闭闹钟。

## 产品验收指标

- 应用睡眠后恢复时，不因错过某一秒而永久漏响。
- 一次性闹钟只有在成功进入播放或明确 fallback 后才被视为处理完成。
- 共享数据文件损坏时，启动不会静默清空列表。
- 同一用户从两个应用路径打开时能读到同一份数据。
- 起床确认关闭时，交互路径与普通闹钟一样短；开启时，界面明确显示“未确认”和“已确认”。
